Actúa como un experto en descompilación de Nintendo 64 (MIPS III, GCC 2.7.2 con optimización -O2).
Queremos reconstruir la función C para lograr un 100% de matching binario contra el archivo original.

Archivo destino: src/main/puzzle.c
Función: Init3DPuzzle

Prototipo exacto:
s32 Init3DPuzzle(struct tetWell *well, struct cursor_t *cursor, u8 *ptr, s32 number);

Estructuras y tipos confirmados del proyecto:
- En include/cursor.h:
  cursor->target[0] (offset 0x28)
  cursor->target[1] (offset 0x2C)
- En include/tetwell.h y include/block.h:
  well->block[BLOCK_LEN_ROWS][BLOCK_LEN_B] donde sizeof(block_t) es 0x2C (44 bytes)
  stride por fila: 18 * 44 = 792 (0x318)
  campo en offset 0x10: well->block[x][y].type
- Función externa llamada al inicio:
  Init3DTetrisBlocks(well, 0);

Observaciones clave del ensamblador MIPS:
1. $s1 es decrecido: addiu $s1, $s1, -1. Si number <= 0 salta el primer bucle (blez).
2. Primer bucle (.L80088D70): lee un byte u8, avanza ptr += (byte << 1) + 2.
3. Si el siguiente byte leído es 0: asigna cursor->target[0] = 0 y retorna 0 (no toca target[1]).
4. Si no es 0: asigna cursor->target[0] y cursor->target[1] con *ptr.
5. Segundo bucle (.L80088DBC): itera count veces. Lee dos bytes: packed y row.
   El desplazamiento para extraer el tipo es lógico (srl a1, a0, 4), por lo que packed debe tratarse como entero sin signo (u8 / u32) para no generar 'sra'.
   Escribe: well->block[packed & 0xF][row].type = packed >> 4;
6. Al terminar el segundo bucle, retorna -1 incondicionalmente.
